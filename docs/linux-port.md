# Linux migration status

The Linux rewrite uses Rust and QuickGUI, with the macOS application as its feature and UI reference. The UI work is complete for the clarified target: preserve functionality and provide a polished Linux interface; exact macOS appearance is not required. The original Swift application remains the behavior reference and macOS build. Acceptance checks and platform differences are recorded below. Native macOS execution is unavailable on this host, so these checks do not claim identical results for every macOS operation or edge case.

### Stroke rendering

QuickGUI's original path antialiasing reduced a requested two-pixel line to roughly one pixel of coverage and made subdivided diagonals uneven. Stroked paths now use an inset core and an outward coverage fringe with shared boundary normals. Thin cores use the tessellator's centerline. Reflection, nonuniform scaling and display scale preserve stroke coverage. Expanded paint bounds keep the fringe in clipping and overlap ordering. Filled paths retain their previous renderer.

Two GPU regressions cover straight and subdivided lines, corners and circles at widths 0.5, 1, 2 and 12, display scales 1, 1.5 and 2, fractional clipping, reflections and half opacity. Coverage matches geometric area within the test tolerances; wider strokes also compare against SVG rendering. Separate tests cover fringe admission against the unchanged GPU vertex cap and cross-primitive overlap order. Stroke metadata counts against the existing retained-path byte limit. Fringe triangles consume more of the existing per-frame budget, so exceptionally large scenes can reach it sooner.

## Architecture

- QuickGUI 0.1.5 provides the native window, controls, input, clipboard, file dialogs, and worker pool. A pinned local copy sets Linux application identity, exposes a window-connected clipboard provider, and supports opaque native select popups with correct X11 focus; see `vendor/README.md`.
- Rust owns documents, immutable pixel assets, edit transactions, bounded undo history, selections, compositing, project I/O, and tool interactions. wgpu/Vulkan accelerates large brushes, canvas compositing, and high-quality preview reductions, with a CPU fallback.
- The existing portable C kernels implement healing, content-aware fill, noise, lens correction, and magic-wand selection on both platforms.
- libheif decodes HEIC; Little CMS converts embedded RGB, grayscale, CMYK, and Lab profiles to sRGB. Lab TIFF supports CIELab/ICCLab, 8-bit/16-bit samples, planar storage, alpha, orientation, declared white points, both byte orders, and BigTIFF.
- Full BiRefNet Dynamic through native Rust/ONNX Runtime CUDA replaces Apple's Vision foreground segmentation. The model is cached between operations; Python is not required. Model results are not pixel-identical to Apple's model. Advanced refinement ports the guided-filter algorithm from the Swift app.
- Projects use the existing directory-based `.comp` format, versions 1 through 7. Saves write version 7 and atomically exchange complete packages on Linux. Unsupported metadata is rejected instead of silently discarded.

Platform differences and verification limits:

- BiRefNet Dynamic replaces Apple's proprietary Vision model. The removal tool, editable mask and advanced refinement are implemented, but the model's output differs from Apple's.
- Vulkan calculations match the CPU reference within two 8-bit channel values in compositor tests and one value in brush tests. These checks do not establish identical performance or pixels on every macOS/GPU combination.
- Hardware Vulkan accelerates supported workloads. Small regions, software-only adapters and scenes beyond the GPU buffer budget retain the CPU path. Document/history assets remain in CPU memory. See the measurements below for the tested workload.
- The macOS 100-million-pixel raster budget remains in effect. A sparse canvas can be larger; operations requiring oversized occupied raster assets report the limit before committing an edit.
- Linux keyboard shortcuts use Ctrl and Alt. Native dialogs and clipboard integration use the desktop's portal and X11/Wayland services. Other compositor versions and multi-seat setups have not been exhaustively tested.
- Project compatibility tests follow the Swift serialization schema. The Swift/Xcode suite and opening Linux-saved projects in the macOS application have not run on this host.
- The release archive targets x86_64 Linux with glibc 2.39 or newer and the documented runtime dependencies. Ubuntu 24.04 is the build baseline, not the only supported distribution.
- Release signing is intentionally omitted. Local artifacts and the unsigned HTTPS feed are prepared. Publishing a GitHub release is a separate, externally visible release action and has not been performed.

### Native GPU background removal (initial CUDA implementation)

This section records the earlier CUDA implementation and its measurements. The universal Vulkan implementation below supersedes its runtime packaging and device selection.

Background removal now uses the Rust `ort` crate with native ONNX Runtime 1.30.0 and CUDA 12. A process-wide session stays loaded between worker jobs. The editor passes RGB tensors and receives mask pixels in memory, with no Python subprocess, interpreter environment, or intermediate PNG files. Applying and refining masks retains the existing source-pixel, selection, history and cancellation handling.

The previous General export exceeded available VRAM on the RTX 3070 Ti, including its half-precision variant. The replacement is full **BiRefNet Dynamic**, using the ONNX community's CUDA export with native `DeformConv`, FP16 input/output and fixed 1024 × 1024 input. This changes the weights from the previous General checkpoint; it is not the Lite model. Preprocessing follows the export's bilinear RGB resize and ImageNet normalization. The CUDA graph already includes sigmoid; its alpha is decoded directly without a second sigmoid or contrast stretching. The explicit CPU option uses the full-precision Dynamic export and decodes its logits with sigmoid.

Model sources are pinned to immutable revisions and SHA-256 hashes in `scripts/setup-background.sh`:

- CUDA: `onnx-community/BiRefNet_dynamic-1024x1024-ONNX-CUDA`, revision `5e8a5a4aa9b0e0342a22ef6e47e456dd4fd9c4b9`.
- CPU: `onnx-community/BiRefNet_dynamic-1024x1024-ONNX`, revision `6defd3a19cec21042b178108815c9c4508d09867`.

Setup installs native libraries, their license notices and models under `$XDG_DATA_HOME/compositor/inference` (default `~/.local/share/compositor/inference`). Source and standalone executable installations use this setup script. The AppImage bundles these files at build time and requires no setup. No root access or Python is required. Downloads are verified before use, and complete library files replace old files by rename so a setup rerun does not truncate libraries mapped by a running editor. `COMPOSITOR_INFERENCE_DIR` overrides this directory. CUDA initialization failures are reported instead of silently running on the CPU. Machines without the NVIDIA driver select CPU inference automatically. `COMPOSITOR_BACKGROUND_DEVICE=cpu` explicitly selects CPU inference.

On the 512 × 512 astronaut fixture, the old Python/CPU pipeline took 31.96 seconds. The release-build native path took 9.17 seconds on the first removal, then 0.553, 0.540 and 0.563 seconds with the cached model. These measurements include preprocessing and mask decoding, exclude editor presentation, and vary with system load. The new and previous cutouts have 99.824% foreground intersection-over-union at alpha 128, a mean alpha difference of 0.779/255, and a 99th-percentile difference of 4/255. The inspected comparison is `dist/screenshots/linux-native-background-comparison.png`; this single fixture does not establish identical output on every image.

The hardware regression invokes the editor's cached inference path twice, checks session reuse and identical repeat masks, and verifies through ONNX profiling that Conv, DeformConv and MatMul execute on CUDA. CPU shape/bookkeeping nodes remain expected. Ordinary regressions cover RGB tensor layout, normalization, alpha preservation, dimensions and malformed output. `cargo run --release --example background_benchmark -- photo.png` measures cold and cached removals without modifying the source photo.

### Universal Vulkan background removal

One AppImage now bundles the native ONNX Runtime 1.30.0 CPU core, Microsoft's WebGPU 0.3.0 plugin, and both full BiRefNet Dynamic models. The plugin uses Vulkan for NVIDIA and AMD GPUs, avoiding the CUDA/cuDNN distribution stack that made the previous bundle exceed GitHub's 2 GiB release-asset limit. Automatic selection requires a hardware Vulkan adapter with FP16 shader support; otherwise it selects the bundled CPU model. `COMPOSITOR_BACKGROUND_DEVICE=cpu` or `gpu` overrides selection. GPU initialization and inference failures remain visible errors, preserving the layer.

The GPU model retains the pinned CUDA export's weights, FP16 precision, 1024 × 1024 input and probability output. At build time, `scripts/background_model.py` replaces its 20 deformable convolutions with equivalent bilinear GridSample, mask multiplication and convolution operations supported by Vulkan. Packing kernel positions into the sampling grid avoids large GatherND intermediates. Constant shape calculations are folded during packaging to reduce model-loading time. Build-only Python dependencies are pinned; neither Python nor conversion code ships in the AppImage. Source assets and the transformed model have pinned SHA-256 checksums.

Reference tests compare the lowering with ONNX Runtime's native DeformConv for different kernel sizes, convolution and offset groups, strides, dilation and padding. Maximum error in those FP32 operation tests is 0.00000763. On the astronaut fixture, the optimized Vulkan mask and the original CUDA mask have 99.973% foreground intersection-over-union at alpha 128 and mean alpha difference 0.0494/255. This fixture does not establish identical results for every image.

The hardware regression exercises two removals through the editor's cached session and verifies that Conv, GridSample, MatMul and LayerNormalization kernels execute on WebGPU. The native plugin reads Vulkan and buffer-cache settings from session configuration entries. Storage-buffer caching is disabled to avoid retaining oversized temporary allocations on 8 GB cards. Application shutdown waits for active inference, destroys the native session before graphics-driver teardown, and rejects queued inference. Leaving the static session alive caused an NVIDIA compiler-thread crash during process exit; the hardware regression now checks explicit shutdown too. Physical AMD hardware has not been available for validation.
